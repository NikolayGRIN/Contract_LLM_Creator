Contract LLM Creator (Offline)

Offline-система для анализа, структурирования и контролируемой генерации договорных документов с использованием локальной LLM.


Общее описание проекта

Contract LLM Creator — это offline-пайплайн для работы с юридическими документами.  
Система предназначена для предобработки, структурного анализа и последующей генерации договоров без использования облачных сервисов и внешних API, что критически важно при работе с данными, составляющими коммерческую тайну юридических лиц.

Проект ориентирован на практическую юридическую NLP-задачу:
- сегментацию договоров на логические разделы (clauses),
- формирование структурированного корпуса договоров,
- контролируемую генерацию договорных разделов на основе реальной контрактной практики.

Цели проекта

Целью проекта является разработка сквозного оффлайн-пайплайна, который:

- обрабатывает и анализирует реальные договорные документы;
- сегментирует договоры на логические разделы;
- формирует локальный корпус контрактных клауз;
- реализует методы лексического и семантического поиска прецедентов;
- интегрирует локальную языковую модель для гибридной генерации;
- генерирует новые договоры и их отдельные разделы по параметризованному пользовательскому запросу;
- внедряет автоматический контроль качества созданного документа;
- поддерживает двуязычную генерацию (русский, английский);
- обеспечивает полностью оффлайн-инференс.


1. Предобработка и сегментация договоров 

- извлечение текста из DOCX-файлов (включая таблицы);
- очистка и нормализация договорного текста;
- выделение заголовков и сегментация на логические разделы;
- сопоставление заголовков с унифицированной типологией клауз;
- корпусный анализ качества сегментации.

Ключевые полученные файлы:
- `contracts_docx_healed`
- `segments.csv`
- `segments_report.csv`


2. Формирование локального корпуса договоров 

- преобразование договоров в структурированные форматы (`corpus_sections.jsonl`);
- сохранение порядка разделов и метаданных;
- поддержка статистического и покрывного анализа корпуса;
- разделение физических документов и логических контрактных структур.


3. Лексический поиск (BM25) 

- лексико-статистический поиск релевантных прецедентов;
- фильтрация по типу секции (`payment_terms`, `delivery_terms`);
- диверсификация результатов (дедупликация, shingles);
- маскирование переменных из пользовательской формы.

Ключевой модуль: `src/retrieval/bm25.py`


4. Семантический поиск (Embeddings Retrieval)

Дополнительно реализован поиск по векторным представлениям текста, обеспечивающий учет смыслового сходства между фрагментами.

- автоматическое разбиение текстов на чанки;
- вычисление embedding-векторов;
- построение и кэширование индекса (emb_index.pkl).

Используемая embedding-модель: bge-m3-q4_k_m.gguf

Данный подход расширяет покрытие корпуса и повышает качество retrieval для секций, где ключевые слова могут отличаться, но смысл остается близким.

Ключевой модуль: `src/retrieval/embedding_index.py` 


5. Контролируемая генерация договоров с использованием локальной LLM 

- генерация отдельных разделов договора (Payment Terms, Delivery Terms);
- строгая параметризация через `form_input.json`;
- поддержка русского и английского языков;
- генерация длинных юридических списков (20+ подпунктов);
- автоматическая валидация структуры и содержания;
- retry-механизм при нарушении требований.

Реализованные стратегии генерации

В системе применяются три взаимодополняющие стратегии формирования текста.

5.1 Prompt-based (form-driven) генерация

Раздел формируется языковой моделью исключительно на основе:
- структурированного промта;
- значений параметров формы (цена, сроки, валюты, условия и т.д.);
- заранее заданных требований к объёму и структуре.

Текст генерируется «с нуля» без использования шаблонов или готовых фрагментов корпуса.
Метод применяется для генерации следующих разделов: 
1. ОПРЕДЕЛЕНИЯ
2. ПРЕДМЕТ ДОГОВОРА
3. ЦЕНА И НАЛОГИ


5.2 Retrieval-based генерация (BM25 - лексический поиск, опирается на совпадение слов)

Формирование текста осуществляется на основе найденных релевантных прецедентов корпуса, которые используются в качестве исходного материала для последующей обработки языковой моделью.

В отличие от генерации «с нуля», модель получает конкретные фрагменты реальных договоров и выполняет:
- отбор наиболее информативных положений;
- нормализацию формулировок;
- стилистическое выравнивание текста;
- объединение и структурирование нескольких прецедентов;
- адаптацию содержания под параметры пользовательской формы.

Метод применяется для генерации следующих разделов: 
4. УСЛОВИЯ ОПЛАТЫ
5. УСЛОВИЯ ПОСТАВКИ


5.3. Retrieval-based генерация (Embeddings - семантический поиск)
Для построения векторных представлений применяется embedding-модель `bge-m3-q4_k_m.gguf`
Модель запускается локально через llama-cpp-python и используется исключительно в оффлайн-режиме.
Реализовано:
- рассчитаны embeddings для всех фрагментов корпуса (corpus_sections.jsonl);
- построен и кэширован локальный векторный индекс (emb_index.pkl);
- поиск выполняется по cosine similarity;
- отбор: top-k + фильтрация по section_id + дедупликация.
- повторная векторизация при последующих запусках не выполняется.

Метод применяется для генерации следующих разделов: 
6. ПРИЕМКА И ИНСПЕКЦИЯ
7. ГАРАНТИИ
8. ОТВЕТСТВЕННОСТЬ И ШТРАФЫ
9. ФОРС-МАЖОР
10. ПРИМЕНИМОЕ ПРАВО И СПОРЫ


Ключевые модули:
- `run_generate.py`
- `src/generation/*`

6. Экспериментальные результаты
Проведена полная автоматическая генерация договоров без ручной правки.

Сформированы:
- договор поставки станков (RU) - `Results/Контракт русский`;
- contract for delivery of crude oil (EN) - `Results/Контракт английский`.

Дополнительно в ходе экспериментов были исследованы характеристики корпуса и влияние параметров retrieval и chunking на качество генерации.

Проведен количественный анализ структуры данных:
- рассчитано распределение количества разделов по типам и языкам,
- измерена средняя и перцентильная длина секций в токенах,
- определено покрытие корпуса по каждой клаузуле,
- оценено среднее число фрагментов (чанков), приходящихся на одну секцию.

Также подтверждено, что:
- лексический поиск BM25 стабильно работает на юридических текстах благодаря высокой повторяемости терминологии,
- использование эмбеддингов целесообразно для длинных и вариативных разделов,
- гибридный подход (form-based + retrieval + LLM) обеспечивает более предсказуемое качество по сравнению с чистой генерацией.

В результате сформирована дифференцированная стратегия генерации:
- короткие и формализованные разделы собираются шаблонно,
- средние по объему — через BM25 + LLM,
- длинные и вариативные — через embeddings + LLM.

Это позволило сократить время инференса, уменьшить число ошибок структуры и повысить повторяемость результатов.

Подтверждена практическая работоспособность пайплайна для реальной генерации договорных документов.
Сгенерированные договоры соответствуют структуре, обладают достаточным лексическим разнообразием и в целом корректно отражают параметры формы.

7. Метрики качества генерации

Для количественной оценки результатов генерации использован набор формализованных метрик, позволяющих автоматически проверять структурную корректность, содержательную полноту и текстовое качество сгенерированного договора.

Рассчитываются:
- полнота структуры — доля присутствующих обязательных разделов
- корректность нумерации — валидность иерархии пунктов
- объём разделов — соответствие минимальному размеру
- лексическое разнообразие — доля уникальных слов
- дословные повторы — количество идентичных фрагментов
- соответствие форме — совпадение с параметрами form_input.json
- фактические несоответствия — число содержательных ошибок

Достигнутые результаты:

Полнота структуры: 1.0 (100%)
Нумерация: корректна
Объём разделов: достаточный
Лексическое разнообразие: 0.466
Дословные повторы: 0
Соответствие форме: 0.90
Фактические несоответствия: 2


8. Особенности архитектуры
- полностью оффлайн-инференс (корпус, модели и индексы хранятся локально);
- все вычисления выполняются на стороне пользователя;
- использование GGUF-модели (qwen2.5-7b-instruct-q4_k_m.gguf);
- backend: `llama-cpp-python`;
- запуск на CPU и GPU;
- поддержка многоязычной генерации с автоматическим выбором русского/английского языка на основе параметра `language_mode` в `form_input.json`.


9. Академический контекст

Проект разрабатывается в рамках итоговой работы по программе переподготовки и ориентирован на разработку оффлайн-системы автоматизированной генерации договорных документов.

В работе реализованы и исследованы:
- корпусная сегментация и структурирование реальных договоров;
- формирование типизированного корпуса клауз;
- лексический retrieval (BM25);
- семантический retrieval на основе embeddings;
- локальная генерация текста с использованием LLM;
- гибридная Retrieval-Augmented Generation архитектура;
- автоматические метрики и процедуры валидации качества.

Практический результат:
- создан воспроизводимый оффлайн-пайплайн генерации договоров;
- подтверждена возможность использования локальных LLM без облачных сервисов;
- продемонстрирована применимость методов RAG к юридическим текстам.

Работа направлена на интеграцию методов NLP и реальной договорной практики для задач автоматизации юридического документооборота.
